# Quests (v33): data, build, screen, progress

The Quests tab (key `Q`, link segment `s1Q`) lists the game's quests, shows where a save stands and lets the player mark progress by hand. Every quest fact comes from the
game's files or from the save; **no third-party guide, wiki or spreadsheet is used for data** (the credit link to ChrisRi's Optimal Quest Order Guide is a plain link, nothing of it is copied or loaded).
Spike notes with the file formats: `~/work/w3planner-art/quest-spike/FORMAT-NOTES-quests.md` (not committed).

## Making the data
`python tools/make_quests.py` (inputs read-only: `~/incoming/w3planner-journal.zip`, `~/incoming/gamedata/en.w3strings`, `~/incoming/gamedata/csv/**/*quest_levels*.csv`; `--check` compares with the files on disk).
- `data/QUESTS.json` (committed, 313 KB, loaded as a script when the Quests tab or the import dialog opens: `/*@file:QUESTS*/`): `{v, regions:[[key,label]...], quests:[{g, id, n, t, r, lv, p, o}]}`. `g` = the quest's journal GUID (32 hex digits: how a save names it), `id` = the journal `baseName`,
  `n` = name, `t` = main | side | contract | treasure | gwent | race | fist, `r` = region key, `lv` = level or null, `p` = pack (startup, bob, ep1, dlc0), `o` = objectives `[[GUID, title], ...]` in the game's order (phases by `order`, objectives by `order`). Names and objective titles are short labels (like skill and item names); **the journal text is not in the repo**.
- `~/work/w3planner-art/quests/desc.json` + `manifest.json` (game text, never committed, like the Glossary): `{quest id: [description entry, ...]}` in the game's order, with the game's tags (`<br>`, `<i>`, `<b>`, `<font color>`, `<<button>>`). `tools/build.py --variant game` makes it one hashed script, `quests/desc.<hash>.js` (`W3DATA.quests_desc`), loaded when a quest is opened; the public and offline builds have none and say "Journal text is not included in this build." The tests build with a tiny invented fake (`tests/fixtures/quests`, `--quests-dir`).
- **Type** (`t`): the journal's `type` (absent = Story, Chapter) is Main, Side Secondary, MonsterHunt Contracts, TreasureHunt Treasure hunts; Gwent (group `Gwint`, titles starting "Gwent:", and the card-collection quest "Collect 'Em All"), Races (titles "Race:" / "Races:") and Fistfights (titles "Fists of Fury") are told apart from the game's own group and titles (the game has no such type).
  Note: "Deserters" (`LW_Prologue_Deserter_Camps`) is a Chapter-type quest in the game's Living World group and so lands under Main; it has no region code, so it is in Other & epilogue.
- **Regions** (decisions by Vivek, 2026-10-17): tabs White Orchard (`world` code 4), Vizima (5), Velen (9), Novigrad (1), Skellige (2), Kaer Morhen (3), Hearts of Stone (every quest of the ep1 pack: 26), Blood and Wine (every quest of the bob pack: 83, including Envoys, Wineboys), Other & epilogue (code 8 and no code, nothing guessed). Free-DLC quests take their region from their code. The code to place mapping is inferred from the quest ids (the scripts never name it).
- **Dropped** (debug, placeholder, demo; 15): the 8 quests with no title (`BidDebugQuest`, `BidDebugQuest2`, `Combat`, `Quest Tutorial 01`, `TEMP Minor Testing Def`, `Lynx Set Upgrades`, `Treasure hunt template`, `Tips & Tricks`), the group `testlevel` (`[PL] Exploration`, `[Interaction]`) and the E3 / press demo leftovers (`E3 2013`, `E3 2013 Fake`, `E3 2014`, `E3 2014 Griffin`, `MS 2014 Werewolf`).
- **Level**: `gameplay/globals/quest_levels.csv` of the base game and every DLC (`;`-separated, key = the quest `baseName`, case and surrounding spaces ignored). 397 of 401 quests have one. A level with no source is `null`: the page shows "—" with the tooltip "not computed yet", never a guess.
  Fixes, each with its game-file source: the five `plegmund_poi_01` to `_05` (Big Feet to Fill) use the one row `plegmund;40` (`dlc/bob/data/gameplay/globals/quest_levels.csv:71`); `ep1poi26b` (A Dark Legacy) uses `ep1poi26;38` (`dlc/ep1/.../quest_levels.csv:24`); the seven Wolf School scavenger hunts (`Wolf Set` 14, `Wolf Upgrades 1A` 21, `1B` 21, `2` 29, `2b` 29, `3` 34, `3b` 34) are in `dlc/dlc10/.../th1009_quest_levels_copy.csv` (the old glob missed the file). A key in two files with different levels (`mq1058 cat stash`: dlc10 15, dlc15 25) takes the canonical `quest_levels.csv`.
  No source (level stays empty): `cammerlengo` (Knight for Hire), `mq1060_armor_upgrades` (Scavenger Hunt: Forgotten Wolf School Gear Diagrams), `Q309 Novigrad Under Control 2` (Novigrad, Closed City II), `Q401 Megascope` (Disturbance).
- Six objective GUIDs appear under two quests (Q704 Starting and Q704B Fairy Land share 5, Q310 Ciri's Night Out and a Chapter 3 quest share 1): the game's files repeat them. A save marks them once; both quests show the same state.

## The XP rule (zones and tooltips)
`r4Game.ws`, `OnGiveReward` (lines 1020 to 1078; constants `gameParams.ws` 456 to 459): `lvlDiff = quest level - player level`. At `lvlDiff <= -10` the modifier is 0 and the game then gives **5 %** of the reward XP; otherwise 1.0 (Death March and Blood and Broken Bones lower it to 0.8 and 0.9: not modelled). **Hearts of Stone only** (reward names containing "q60"): while `lvlDiff < 10` the modifier is `1 + lvlDiff x 0.16`, at most 1.5, at least 0 (0 gives the 5 %). So in the Level band a quest is in the hatched "5% XP" zone when its level is at most `my level - 10`, and "full XP" otherwise; a Hearts of Stone quest shows its own percentage in the tooltip (`qsXp` in `src/quests.js`). Not modelled: the New Game Plus level offset and the NG+ 50 % rule, the difficulty. The planner applies the Hearts of Stone rule to all 26 quests of the pack (the pack's reward file names only the q601 to q605 rewards with "q60"; the treasure hunts' reward names were not checked).

## The screen (`src/quests.js`, `quests.css`; the tab in `screens.js`)
Region sub-tabs with % done (done / quests of the region) | Next up (4 cards) | view switch **Timeline** (disabled: "Needs base-game quest data · coming next"), **Level band**, **List** | detail panel. Only the screen (`s1Q`) is in the link; region, view, chips, search and selection are not.
- **Next up**: active quests first (nearest to my level, with the current objective from the save, "not known" for a hand-marked one), then quests not started that still give full XP and have a level, closest to my level, those in the region of the first active quest first (there is no map data to measure distance), then by level.
- **List**: ordered by level (no level last), status icon, name, level; chips All, Main, Secondary, Contracts, Treasure hunts, Gwent, Races, Fistfights, Hide done; the search looks in every region.
- **Level band**: one row per type present in the region, level 1 to 60 on x, a line at my level (the Level field of the bar), the 5 % zone, done quests hidden, dots stacked in lanes; hollow = not started, filled gold = active, dashed = inactive, red ring = failed, a rotated square = Hearts of Stone. On a phone the band scrolls sideways inside its own box.
- **Detail**: name, "type · region · level", the XP at my level, the save's status ("No save imported" / "In your save: Active"), the current objective(s) (active objectives of the save), **My progress** (Not started, Active, Done, Failed; "Follow my save" removes the mark), the journal text (all description entries in the game's order, loaded on demand, the game's tags as elements, never `innerHTML`), the objective list with done / active from the save. Not shown: fail conditions (the base game's quest graphs are not available here).
- Key `Q` opens the tab from any screen (not while typing, not over a dialog or the slot panel). The arrows and swipe step Glossary, Inventory, Quests, Character.

## Progress storage
`localStorage['w3p.quests.v1']` = `{v:1, manual:{questGuid: none|active|done|failed}, save:{at, file, q:{questGuid: done|active|failed|inactive}, o:{objectiveGuid: ...}}, changed}`. Every read and write is in try/catch; if storage is unavailable the screen works for the visit and the chip says "Not saved in this browser". A quest's state is its hand mark if it has one, else the save's, else Not started. The chip **Saved in this browser ▾** (top bar, on this tab): count marked, last change, **Export progress (.json)**, **Load progress file** (strictly validated: GUIDs and states only, 2 MB at most), **Reset** (asks first). Nothing is sent anywhere (the site makes no requests but GETs of its own files) and nothing about quests is in the build link.
**Import save over progress**: the review's Quests section shows the counts and, when this browser already has progress, a table (Now | Keep my hand-ticks | Replace all) and three choices: *Use save, keep my hand-ticks* (default; the save layer is replaced, hand marks stay), *Replace everything with save* (hand marks are dropped), *Cancel* (quest progress stays as it was; the rest of the import still applies). The save's journal reading is in `docs/IMPORT.md` ("The journal").
